# Anger Foot: technical

## How the game stores text

Unity 2019.4.35f1, Mono. Every line is a `LocalizedString : ScriptableObject` in
`resources.assets` (1776 entries, 1774 with text; two are empty in the original too), each with
12 translations indexed by the language's position in the alphabetical
`LocalizationLanguage.SpreadsheetKey` list:

```
CHINESE SIMPLIFIED, CHINESE TRADITIONAL, FRENCH, GERMAN, ITALIAN, JAPANESE,
KOREAN, PORTUGUESE BRAZILIAN, RUSSIAN, SPANISH, SPANISH LATAM, TURKISH
```

The Italian slot (index 4) is **empty and hidden from the menu**: the record exists, text never
did. That is the slot we take. `SpreadsheetKey` must stay `ITALIAN` or every index shifts
(Polish would show Korean, etc.). Language record: `LocalizationLanguage : ScriptableEnum`
(`Assembly-CSharp-firstpass.dll`) with `Supported`, `NativeName`, `SpreadsheetKey`,
`LanguageTag`, `SteamAPIName`, `GOGAPIName`, `FontOverride`.

Each line carries speaker and addressee with gender (`NPC (Female)` > `Player`) and a developer
note (`Description`).

## Plugin

`plugin/Plugin.cs`, BepInEx 5, two Harmony patches:

- `LocalizationManager.Initialize` prefix: renames the Italian record (`NativeName` "Polski",
  `LanguageTag` `pl`, `Supported` true) before the language list is built.
- `LocalizedString.GetTranslation` postfix: returns our text when the taken slot is active.
  No waiting for asset loading, no `EnsureInstancesAreLoaded`.

**Match by GUID, not term.** Terms repeat (1518 unique of 1776); GUIDs are unique 1776/1776.
Review entries point to objects by `id` (Unity `path_id`), invisible at runtime, so
`build_plugin.py` reads the original `resources.assets` and writes `pl.tsv` as `GUID<TAB>text`.
Log lines on a healthy start: "Italian slot renamed to Polish…", "First Polish text served…".

## Files

| File | Purpose |
| --- | --- |
| `translations/en-pl-review.json` | 1774 entries; `id` = path_id, `key` = `<path> [speaker > addressee]` (report matches gender on it), `context` = developer note. |
| `translations/structure.yaml` | Generated by `tools/structure.py`: 13 groups, 294 conversations (order from line number, speaker from key; NPCs as npc-m / npc-f). Rerun after dialogue keys change. |
| `tools/assets.py` | Text asset layout (slot, entry parser). |
| `tools/ref_extract.py` | Table with speaker/addressee + RU/FR/DE/ES → `work/ref-all.json`. |
| `tools/review.py` | Refreshes `en-pl-review.json` from `work/ref-all.json`, keeping Polish. |
| `tools/extract.py` | Dumps every LocalizedString to JSON (original extraction). |
| `tools/build_plugin.py` | GUID map, plugin compile, package. |

## Build

```powershell
.venv\Scripts\python.exe games\anger-foot\tools\ref_extract.py "C:\Games\Anger Foot\Anger Foot_Data\resources.assets"   # only for review.py
.venv\Scripts\python.exe games\anger-foot\tools\build_plugin.py --game "C:\Games\Anger Foot"
```

Checks every translated entry found its GUID, GUIDs are unique, no game file in the archive.
Output: `dist/Anger-Foot-PL-<version>.zip` + BepInEx source archive (LGPL). No checksum pin;
binds by class names. Earlier the translation shipped as rewritten `resources.assets` +
`sharedassets0.assets` (193 MB); the plugin package is ~0.7 MB.
